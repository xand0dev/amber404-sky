## 1. Мета
Екіпаж дрона за 30 секунд бачить для будь-якої точки України **напрямок і силу вітру на будь-якій висоті 10–500 м** (плавно), нижню межу хмар з точки роси, пориви, обмерзання — і вердикт GO / CAUTION / NO-GO з причиною, по годинах на 48 год уперед. Для маршруту A → B — розріз вітру й найкраща висота.

**Звідки вимоги:** дзвінок з досвідченим оператором дронів 26.11: дивляться напрямок і силу вітру по висотах (мале небо до ~90 м, шари до 500 м), точку роси (хмари), будь-яку точку карти, хочуть зберегти погоду й поділитися. Зараз — UAV/Drone Forecast, одна підписка на п'ятьох.

### Критерій успіху (неділя, 15:00 CET)
Сайт на GitHub Pages зі справжнім прогнозом, оновленим не пізніше 6 год тому: живий вітер на карті, вердикт для точки й профілю, вікно для польоту, Galileo і клімат Copernicus ERA5.

## 2. Користувач
Командир або оператор екіпажу дронів Сил оборони: FPV 7–10″, важкі мультикоптери, крила VTOL. Перед зміною дивиться вітер по висотах і хмари, щоб вирішити: летіти чи ні, на якій висоті, чи вистачить батареї на шлях назад. Зараз — Windy (карта без вердикту) і UAV Forecast (вердикт без карти, одна точка, одна підписка на п'ятьох). Другий ринок — **агро**: оператори агродронів на полях (той самий вітер, інший дрон). Також ДСНС і розмінування.

## 3. Демо · 30 секунд
1. Відкриваємо сайт → над Україною тече вітер на 120 м, кольором — швидкість.
2. Обираємо «FPV 7″, 50 м» і шар «Можна летіти» → країна фарбується GO / CAUTION / NO-GO.
3. Клік на поле під Полтавою → вердикт з причинами і «Найближче вікно: сб 10:00–14:59».
4. ▶ — прокручуємо 48 год, бачимо, як проходить фронт.
5. Панель Galileo: скільки супутників видно і PDOP; клімат ERA5: «у грудні льотних лише 46% годин».

## 6. Контракти
Файли в `web/public/data/`. Час — ISO 8601 UTC. Координати — `[lon, lat]` у geo-полях, `lat`/`lon` у точках. Кожен файл має `generatedAt` і `sources` (id з §8).

### 6.1 `meta.json`
```json
{ "generatedAt": "2026-11-28T09:05:00Z", "mock": false,
  "grid": { "lat0": 52.5, "lon0": 22.0, "step": 0.5, "nr": 18, "nc": 38 },
  "times": ["2026-11-28T09:00:00Z", "... 48 значень"],
  "sources": [{ "id": "openmeteo", "name": "Open-Meteo", "license": "CC BY 4.0, non-commercial",
                "fetchedAt": "2026-11-28T09:03:00Z", "status": "ok", "note": "" }] }
```
`status`: `ok | partial | nodata`. Сітка: рядок 0 = `lat0` (північ), стовпець 0 = `lon0` (захід), індекс точки `i = r * nc + c`.

### 6.2 `profile.json` (замінює forecast.json)
```json
{ "generatedAt": "...", "sources": ["openmeteo"], "levels": [10, 50, 100, 150, 200, 250, 300, 350, 400, 450, 500, 600, 700, 800, 900, 1000],
  "spd": [ /* рівень */ [ /* година */ [23, 17, null, "... nr*nc"] ] ],   // м/с × 10
  "dir": [ [ [330, 12, null, "..."] ] ],                                 // градуси, звідки дме
  "gust": [[...]], "temp": [[...]], "precip": [[...]],                  // × 10, біля землі
  "rh": [[...]], "vis": [[...]] }                                         // %, метри / 100
```
**Як рахується профіль (F1):** для кожної точки й години беремо вітер на 10/80/120/180 м і на рівнях 1000/975/950/925/900/850 гПа; висота рівня над землею = `geopotential_height − elevation`; рівні тиску беремо лише вище 200 м. Сортуємо за висотою й лінійно інтерполюємо **u, v** (не швидкість і кут) на 16 висот: кожні 50 м до 500 м, далі кожні 100 м до 1000 м (для «крил»). Вище останнього рівня — значення останнього. `null` — немає даних.

### 6.3 `galileo.json`
```json
{ "generatedAt": "...", "sources": ["celestrak-galileo"], "elevationMaskDeg": 10,
  "points": [{ "name": "Київ", "lat": 50.45, "lon": 30.52 }],
  "visible": [[9, 8, "... по годинах"]], "pdop": [[1.9, 2.1, "..."]] }
```
`visible[p][h]` — кількість супутників Galileo над маскою кута; `pdop[p][h]` — PDOP лише по Galileo.

### 6.4 `kp.json`
```json
{ "generatedAt": "...", "sources": ["noaa-kp"], "series": [{ "t": "2026-11-28T09:00:00Z", "kp": 3.33, "observed": false }] }
```

### 6.5 `climate.json` (рахується раз)
```json
{ "generatedAt": "...", "sources": ["era5"], "year": 2025,
  "cities": { "Київ": { "fpv7": [67, 74, "... 12 місяців"], "fpv10": ["..."], "heavy": ["..."], "wing": ["..."] } } }
```
% годин місяця, коли профіль пройшов би правила §7.4 (лише вітер, пориви, температура, опади, обмерзання).

## 7. Правила обчислень

### 7.1 Область, сітка, висоти
lat 44.0…52.5, lon 22.0…40.5, крок 0.5° (18 × 38 = 684 точки), 48 годин від поточної. Для довільної точки — білінійна інтерполяція чотирьох вузлів у u, v; для довільної висоти 10–1000 м — лінійна між сусідніми рівнями `levels`. Повзунок висоти — крок 10 м, результат плавний.

### 7.2 Погода для вердикту
`ws`, `dir` — сила й напрямок вітру на обраній висоті 10–500 м; `td` — точка роси з `t` і `rh` (формула Магнуса); `cb` — нижня межа хмар ≈ `125 × (t − td)` м над землею (`assumption`, емпіричне правило); `g` — пориви на 10 м; `t` — температура 2 м; `p` — опади; `rh` — вологість; `vis` — видимість; `kp` — значення Kp для 3-годинного інтервалу, у який потрапляє година.

### 7.3 Каталог дронів (усі числа — `assumption`, звірити з паспортами й операторами, F4)
Карта й вітер однакові для всіх. Різниться лише дрон: ліміти, робоча висота, маса, енергія (акумулятор або паливо).
| id | Клас | Маса, кг | Енергія | Час польоту, хв | Вітер, м/с | Пориви, м/с | Мін. °C | Опади, мм/год | Робоча висота, м |
|---|---|---|---|---|---|---|---|---|---|
| fpv7 | FPV 7″ | ~1 | акум. | 10 | 10 | 13 | −15 | 0.5 | 10–90 («мале небо») |
| fpv10 | FPV 10″ з вантажем | 2–4 | акум. | 8 | 9 | 12 | −15 | 0.5 | 10–150 |
| recon | Квадрокоптер розвідки (клас Mavic) | ~1 | акум. | 30 | 12 | 15 | −10 | 0.2 | 50–300 |
| heavy | Важкий мультикоптер | 15–40 | акум. | 20 | 7 | 8 | −15 | 0.5 | 50–300 (оператор: до 7 м/с летить, 8 — забагато) |
| wingE | Крило електро (клас «Лелека-100») | ~5 | акум. | 150 | 15 | 20 | −20 | 1.0 | 150–1000 |
| wingF | Крило з ДВЗ | 20+ | паливо | 300 | 18 | 23 | −25 | 1.0 | 300–1000 |
| agro | Агродрон (клас Agras) | 40–90 з баком | акум. | 12 | 6 | 8 | 0 | 0 | 2–30 |

### 7.3a Свій дрон і енергія
- **Свій дрон:** тип (мультиротор / крило), маса без вантажу, вантаж, крейсерська швидкість, ліміти вітру й поривів, мін. °C, робоча висота; енергія — **акумулятор** (час польоту в хв) або **паливо** (літри + витрата л/год). Зберігається лише в браузері (OPSEC).
- **Акумулятор:** `T = T_паспорт × k_холод × k_вантаж`. `k_холод` = 1 при `t ≥ 10 °C`, лінійно до 0.7 при −20 °C. `k_вантаж` = `(m / (m + вантаж))^1.5` лише для мультироторів (потужність зависання ∝ маса^1.5). Обидва — `assumption`.
- **Паливо:** `T = літри / витрата × 60`, без холодового множника.
- Резерв 20% завжди. Ефективний `T` іде в зону польоту (§7.5b) і маршрут (§7.5a); на екрані видно, з чого він порахований.

### 7.4 Вердикт
- Немає `ws` → **NO-DATA**.
- **NO-GO**, якщо хоч одне: `ws > вітер`; висота ≥ `cb` (дрон у хмарі); `g > пориви`; `t < мін. °C`; `p > max(опади, 0.05)`; **обмерзання** = `−10 ≤ t ≤ 2` і (`rh ≥ 90` або `p > 0.05`).
- **CAUTION**, якщо не NO-GO і хоч одне: `ws > 0.8 × вітер`; висота ≥ `cb − 60`; `g > 0.8 × пориви`; `t < мін. °C + 5`; `vis < 1000 м`; `kp ≥ 5`; Galileo `visible < 6` або `pdop > 4` (для найближчої точки §6.3).
- Інакше **GO** з текстом «Умови в межах профілю».
- Причини — до 4, спершу NO-GO, потім CAUTION; числа з одним знаком після коми.
- `assumption`: правило обмерзання і пороги Galileo — спрощення; джерела в `docs/SOURCES.md`.

### 7.5 Вікно для польоту
Перший відрізок від поточної години з ≥ 2 послідовних годин GO. Показ у київському часі: «сб 10:00 – 14:59 · 5 год». Немає → «Немає вікна ≥ 2 год до <остання година>».

### 7.5a Зсув вітру, маршрут, знімки
- **Зсув:** зміна напряму ≥ 45° між сусідніми шарами по 50 м при швидкості > 2 м/с — підпис «зсув N°» на профілі.
- **Маршрут A → B:** дуга польоту — набір 15% шляху, крейсер на обраній висоті, зниження 15%. На 40 відрізках: попутна й бокова складові, швидкість відносно землі `√(tas² − cross²) + along`, час туди й назад, найсильніший зустрічний і боковий. «Найкраща висота» — висота 50…500 м з найменшим часом туди й назад без NO-GO.
- **Зберегти погоду:** точка, висота, година, значення й вердикт — у localStorage (до 12); **Копіювати звіт** — текст для чату екіпажу.

### 7.5b Зона польоту (ідея оператора, 26.11)
Від точки старту на обраній висоті: 48 променів через 7,5°, крок уздовж променя; на кожному кроці вітер u, v, попутна й бокова складові, `gs = √(tas² − cross²) ± along`.
- **Туди й назад:** сума `ds/gs_туди + ds/gs_назад` ≤ час польоту × (1 − резерв 20%). Зона найкоротша вздовж вітру, найдовша поперек.
- **Лише туди:** сума `ds/gs_туди` ≤ той самий час. Зона витягується за вітром.
- Промінь обривається, якщо вітер на висоті понад ліміт дрона (червона точка) або вітер ≥ швидкості дрона.
- Час польоту — ефективний `T` з §7.3a (холод, вантаж, паливо).
- Показ: картка з контуром, кільцями відстаней і стрілкою вітру + контур на карті. Власник — F4 (Оля), розрахунок — `web/src/core/zone.ts` (F0).

### 7.6 Шари карти
| Шар | Значення | Шкала |
|---|---|---|
| Вітер | `ws` на обраній висоті 10–500 м | 0…26 м/с |
| Хмари | `cb` — нижня межа хмар | 0…1500 м |
| Пориви | `g` | 0…26 м/с |
| Можна летіти | вердикт §7.4 для профілю й висоти | GO / CAUTION / NO-GO |
| Обмерзання | правило §7.4 | так / ні |
| Температура | `t` | −20…30 °C |
| Видимість | `vis` | 0…40 км |
Частинки вітру завжди рухаються за вітром обраної висоти. Колір — кольором і текстом у легенді та підказці.

### 7.7 Galileo (F2)
Орбіти — Celestrak GP group `galileo` (TLE), розрахунок `sgp4` / `skyfield` на кожну годину для 16 обласних центрів: кількість супутників вище 10° і PDOP лише по Galileo. Супутники зі статусом «not usable» у сповіщеннях GSC — виключити, якщо F2 встигне (інакше `assumption`).

### 7.8 Клімат ERA5 (F2)
Copernicus ERA5, рік 2025, погодинно, 5 міст (Київ, Львів, Харків, Одеса, Дніпро): вітер 10 м і 100 м (для 80/120 м беремо 100 м), пориви, температура, опади, вологість. % годин місяця, що проходять §7.4 без видимості й Kp.

### 7.9 Чесність даних
Час прогнозу й джерела — у панелі. `meta.sources[].status ≠ ok` → плашка на екрані. Дані старші за 6 год → плашка «прогноз застарів».

### 7.11 Телефон і офлайн (PWA)
- Дизайн спершу під 400 px: плашка статусу на всю ширину, кнопки ≥ 44 px, шрифт масштабується (скарга на 17 METEO — дрібний шрифт).
- `manifest.webmanifest` + service worker: застосунок і останній пакет даних (≈ 1,3 МБ gzip на всю Україну, 48 год) у кеші. Без мережі працює все, крім оновлення прогнозу; плашка «прогноз X год тому».
- **OPSEC:** телефон лише завантажує однаковий для всіх файл. Жодних запитів із координатами користувача.
- `web/src/core/` — чистий TypeScript без DOM (вердикт, зона, маршрут, енергія), щоб пізніше взяти в Capacitor або React Native.

### 7.12 Скріншот одним дотиком (P1)
Кнопка 📷 → PNG з того, що на карті (поле, частинки як стрілки, малюнки §7.13, зона), плюс штамп: час прогнозу, висота, дрон, вердикт, джерело, «AMBER Sky». На телефоні — `navigator.share` з файлом (Telegram, Signal), на ноутбуці — завантаження. Збирається з власних Canvas/SVG шарів, без сторонніх сервісів.

### 7.13 Малювання на карті (P2)
Інструменти: точка з підписом, лінія, стрілка, область, текст; колір; скасувати; видалити. Зберігається лише в браузері, експорт/імпорт GeoJSON і KML. Загальні позначки, без бібліотеки тактичних знаків і без шару цілей (Конституція 8).

### 7.14 Власні карти (P2–P3)
Підкладка з файлу користувача, **лише локально, на сервер не йде**: (1) зображення карти (скан топокарти Генштабу тощо) + прив'язка по 3 точках (афінне перетворення, `assumption` для невеликої ділянки); (2) GeoTIFF (`geotiff.js`); (3) MBTiles (`sql.js`). Погодні шари й малюнки — поверх, з прозорістю. Формати, які реально дають екіпажам, — з'ясувати в операторів (Максим).

### 7.10 Доступність
400 px без горизонтального скролу; клавіатура (шари, висоти, профіль, години, точка — Enter на місті зі списку); видимий фокус; вердикт = колір + текст; `prefers-reduced-motion` → замість частинок статичні стрілки.

## 10. Процес
1. `claude` у корені репо; агент читає `CLAUDE.md` → `AGENTS.md`.
2. Перша фраза: «Прочитай specs/F<N>/spec.md і склади план у plan mode».
3. Затвердити план → тести (red) → код (green) → `make check` → руками → PR.
4. Свої папки мерджить власник фічі, спільні — власник F0.
5. Синхронізація — 10 хв кожні 4 год: що злито, що блокує, чи міняємо spec.
6. **Конвеєр агентів — `docs/PIPELINE.md`** (3 воркери: 2 акаунти Claude + Codex, автомерж зеленого CI). **Черга задач.** Кожна задача — GitHub Issue з міткою `agent`, посиланням на `specs/F<N>/spec.md` і 1–4 AC; залежність — «після #N». Один агент = одна задача = одна гілка = один PR зі списком AC ✅/❌ і посиланням на превʼю. Дві задачі на ті самі файли одночасно не запускаємо.
7. **Ніч не простоює:** перед сном у черзі запущено 4–6 незалежних задач.
8. Питання до Олександра в чаті — з `@xand0dev` і `[ARCH]`; решту вирішує чергова F0.
