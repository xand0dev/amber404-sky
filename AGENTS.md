# Інструкції агенту AMBER//404 Sky

Перед роботою прочитай: `CONSTITUTION.md`, `docs/SPEC.md` (§5–7 і свою фічу в §9), `specs/F<N>/spec.md`, `contracts/`.

## Два режими
- **Інтерактивний** (людина поруч) — цикл нижче повністю.
- **Конвеєр** (`docs/PIPELINE.md`, запуск через `claude -p` / `codex exec`, у промпті є «issue #N») — людини немає. Тоді:
  - план не показуєш і «ок» не чекаєш: план — список T1…Tn на початку тіла PR;
  - **нічого не питаєш**: у випадках з «Коли зупинитись» обираєш варіант найближчий до SPEC, пишеш його в розділ PR «Assumptions» (або «Contract requests») і продовжуєш на mocks;
  - крок 5 «Руками» замінює `make check` + e2e у CI; не пиши, що перевірив у браузері, якщо не перевіряв;
  - PR одразу не draft, гілка `feat/F<N>-<issue>`, одна issue = один PR; в тілі «Closes #N».
  - `docs/AI_LOG.md` не редагуєш (паралельні PR конфліктують): рядок AI_LOG — у тілі PR.

## Цикл роботи (інтерактивний режим, не пропускай кроки)
1. **План.** Почни в plan mode: прочитай spec фічі, склади список задач T1…Tn із посиланнями на AC. Покажи людині й чекай «ок».
2. **Red.** Напиши тести з AC (Given / When / Then). Запусти й переконайся, що вони падають.
3. **Green.** Мінімальний код, щоб тести пройшли. Нічого понад AC.
4. **Check.** `make check` — вкажи фактичний результат, а не очікуваний.
5. **Руками.** Для web — відкрий у браузері (400 px і десктоп). Для pipeline — запусти на справжніх даних і покажи 3 рядки результату.
6. **PR.** Таблиця AC → доказ. Draft, поки працюєш.

## Правила
- **Гілка:** `feat/F<N>` або `feat/F<N>-<коротко>` від свіжого `main`. Інтерактивно — один відкритий PR на фічу; у конвеєрі — один PR на issue.
- **Пиши лише у свої шляхи** з `docs/SPEC.md` §9, плюс `specs/F<N>/**` і свій розділ `## F<N>` у `docs/AI_LOG.md` і `docs/SOURCES.md`.
- **Не змінюй** `contracts/`, `Makefile`, `pyproject.toml`, `package.json`, конфіги, `.github/`. Бракує поля — створи issue з міткою `contract` (що, навіщо, приклад) і продовжуй на mocks.
- **Дані:** лише джерела з SPEC §8. Не вигадуй API, полів, координат чи порогів. Без джерела — `assumption` у коді й на екрані.
- **Помилки джерел:** таймаут, 429 чи порожня відповідь → повтор з паузою, потім статус `nodata` з причиною. Ніколи не підставляй дані з попереднього запиту чи іншої точки — це вже було і зіпсувало сітку.
- **Секрети:** ключі (Copernicus CDS) лише в `.env` і GitHub Secrets. Ніколи в коді, логах, PR.
- **AI_LOG:** рядок у своєму розділі: дата | хто | агент / модель | задача | файли | перевірка | PR.
- **Без підписів агента** в комітах, PR, issues і коментарях.
- Інтерфейс українською (англійська — лише якщо лишиться час, F3); документи й коментарі — українською.

## Коли зупинитись і спитати людину (у конвеєрі — не зупиняйся, а запиши в PR, див. «Два режими»)
- AC суперечить SPEC або іншому AC.
- Потрібна зміна контракту, залежність чи доступ, яких немає.
- Джерело даних не відповідає або віддає не те, що в SPEC §8.
